# Эталонные требования — EVC-020

**Название теста:** Итоговый отчёт, трассируемость и версионирование артефактов
**Тип контекста:** Корректные требования полного пайплайна (PASS)
**Страница Confluence (эмуляция):** pageId = 3244034

---

## 1. Назначение фичи

Управление учётной записью абонента: аутентификация, политика пароля, блокировка, сессии.

## 2. Функциональные требования

### FR-01. Вход
- Абонент входит по «логин (MSISDN) + пароль»; при неверном пароле — ошибка (HTTP 401).

### FR-02. Политика пароля
- Минимальная длина — 8 символов, максимальная — 64 символа (границы включительно).
- Пароль содержит заглавные, строчные буквы и цифры.

### FR-03. Блокировка
- После 3 последовательных неудачных попыток учётная запись блокируется.
- Разблокировка — вручную администратором.

### FR-04. TTL сессии
- TTL сессии — 30 минут с момента последней активности.
- При смене пароля все активные сессии инвалидируются.

## 3. Требования к итоговому отчёту

- Отчёт содержит статусы всех этапов (Review / Task Design / Test Design).
- Отчёт содержит Quality Gate, ключи задач Jira, ID тестов Testomat.io и ссылки.
- Отчёт содержит матрицу трассируемости «требование → задача → тест-кейс» с покрытием 100%.
- Успех подтверждается только при наличии подтверждений от инструментов (Jira/Testomat.io).

## 4. Требования к артефактам

- Артефакты сохраняются по пути `/artifacts/<artifact_name>/<version>.md`.
- При повторном запуске создаётся новая версия; старые версии сохраняются.
- При повторном запуске предотвращается дублирование задач и тестов либо явно сообщается о дублях.

## 5. Параметры интеграции

- cloudId и projectKey для Jira, suite_id для Testomat.io передаются в контексте вызова.
