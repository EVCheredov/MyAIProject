# Эталонные требования — EVC-001

**Название теста:** Корректный анализ согласованных требований
**Тип контекста:** Согласованные, непротиворечивые требования (ожидается Quality Gate = PASS)
**Страница Confluence (эмуляция):** pageId = 3407876
**Источник:** `evals/dataset/golden_dataset.json`

---

## 1. Назначение фичи

Управление учётной записью и аутентификацией абонентов в личном кабинете оператора «Super GSM»
(вход в самообслуживание, политика пароля, блокировка учётной записи, управление сессиями,
восстановление доступа по SMS).

## 2. Роли пользователей

| Роль | Описание |
|:---|:---|
| Абонент | Владелец учётной записи, входит в личный кабинет, управляет паролем |
| Администратор | Выполняет ручную блокировку/разблокировку учётных записей |
| Auth Service | Проверяет учётные данные, создаёт и завершает сессии |
| Биллинг | Источник статуса абонента и баланса (используется для проверок до/после транзакции) |

## 3. Функциональные требования

### FR-01. Аутентификация абонента
- Абонент входит в личный кабинет по паре «логин (MSISDN) + пароль».
- При успешной проверке учётных данных система создаёт сессию и предоставляет доступ к личному кабинету.
- При неверном пароле система возвращает ошибку аутентификации `HTTP 401` с телом
  `{"errorCode": "AUTH_INVALID_CREDENTIALS"}`.
- Ответ на неверный логин и на неверный пароль неразличим для клиента (защита от перебора логинов).

### FR-02. Политика пароля
- Минимальная длина пароля — **8 символов**, максимальная — **64 символа** (обе границы включительно).
- Пароль должен содержать не менее одной заглавной буквы, одной строчной буквы и одной цифры.
- Специальные символы разрешены, но не обязательны.
- Пароль хранится только в виде необратимого хеша с солью (алгоритм Argon2id).
- Пароль не выводится в логи, трассировки и ответы API ни в открытом виде, ни в виде хеша.

### FR-03. Блокировка учётной записи
- После **3 последовательных неудачных попыток** ввода пароля учётная запись блокируется на **30 минут**.
- В состоянии «Заблокирована» вход запрещён даже при вводе верного пароля —
  возвращается `HTTP 423` с телом `{"errorCode": "ACCOUNT_BLOCKED", "retryAfterSeconds": <остаток>}`.
- По истечении 30 минут блокировка снимается автоматически, счётчик неудачных попыток обнуляется.
- Администратор может снять блокировку вручную досрочно ( действие фиксируется в журнале аудита).

### FR-04. Управление сессией
- Время жизни сессии (TTL) — **30 минут** с момента последней активности; каждая успешная операция продлевает TTL.
- По истечении TTL сессия завершается, требуется повторный вход (`HTTP 401`, `SESSION_EXPIRED`).
- При смене пароля все активные сессии абонента, включая текущую, инвалидируются.
- Logout завершает только текущую сессию.

### FR-05. Восстановление доступа
- Абонент может восстановить пароль через подтверждение по SMS-коду.
- SMS-код направляется на MSISDN, привязанный к учётной записи.
- Код действителен **5 минут**; допускается **3 попытки** ввода кода, после чего код аннулируется
  и требуется повторный запрос.

### FR-06. Обработка ошибок аутентификации
- При недоступности Auth Service система возвращает `HTTP 503` с телом
  `{"errorCode": "AUTH_SERVICE_UNAVAILABLE"}`; таймаут обращения к Auth Service — 5 секунд.
- При недоставке SMS абоненту возвращается `HTTP 502` с телом `{"errorCode": "SMS_DELIVERY_FAILED"}`,
  предусмотрена возможность повторного запроса кода не ранее чем через 60 секунд.

## 4. Бизнес-правила

| ID | Правило |
|:---|:---|
| BR-01 | Счётчик неудачных попыток сбрасывается после успешного входа и после истечения блокировки. |
| BR-02 | Блокировка учётной записи не изменяет статус SIM-карты в сети и не влияет на баланс абонента. |
| BR-03 | Все события аутентификации (успех, отказ, блокировка, разблокировка) пишутся в журнал аудита. |
| BR-04 | Пароль и SMS-код никогда не попадают в журнал аудита и технические логи. |

## 5. Тестовые данные

- MSISDN для тестов (сгенерированные): `+79991112233`, `+79992223344`.
- Пароль-пример: `SuperGsm2024`.
- Проверка статуса и баланса абонента выполняется до и после каждой транзакции (блокировки/разблокировки).

## 6. Ожидаемый результат ревью

- Противоречий между FR-01…FR-06 и BR-01…BR-04 **не обнаружено**.
- Все ветки (успех, отказ, блокировка, истечение TTL, недоступность Auth Service, недоставка SMS) описаны.
- Границы значений заданы и включительны, обработка ошибок определена.
- **Quality Gate = PASS**; воркфлоу продолжается: создание задач в Jira и тест-кейсов в Testomat.io.
- Запрещено выдумывать отсутствующие противоречия или добавлять новые бизнес-правила.
