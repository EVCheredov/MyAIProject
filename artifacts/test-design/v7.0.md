# СКИЛЛ 3: Проектирование тестов (Test Design) — v7.0

## Фича: EVC-001 «Управление учётной записью и аутентификацией абонентов»
- **Источник требований:** FR-01…FR-06, BR-01…BR-04 (pageId 3407876, PII очищены инструментом `confluence`).
- **Quality Gate:** PASS (передан координатором).
- **Целевой сьют Testomat.io:** `f74c58a3` (API/Security), проект `mytests-ed9d5` — https://app.testomat.io/projects/mytests-ed9d5
- **Дата:** 2026-11-15
- **Базовый абонент для проверок статуса/баланса:** MSISDN `+79991112233`, статус SIM «Активна», баланс `150.00 руб.` (эталон для проверки «ДО = ПОСЛЕ» по BR-02).

## Применённые техники тест-дизайна
- **Эквивалентное разделение:** валидный/невалидный пароль; верный/неверный логин; доставка/недоставка SMS; доступность/недоступность Auth Service; существующий/несуществующий MSISDN.
- **Анализ граничных значений:** длина пароля 7/8/9/64/65; порог попыток 2/3/4; блокировка 30 мин (29:59 / 30:00); TTL 29:59 / 30:00 / 30:01; SMS-код 4:59 / 5:00; 3 попытки ввода кода; таймаут 5 с; повтор SMS 30 с / 60 с.
- **Таблицы решений:** состав пароля (наличие заглавной/строчной/цифры/спецсимвола); блокировка (число неудач × верность пароля × состояние УЗ); событийность аудита.
- **Переходы состояний:** УЗ «Активна → Заблокирована → Активна (авто/ручная)»; Сессия «Активна → Продлена → Истекла / Инвалидирована / Завершена».
- **Телеком-валидация (BR-02):** в каждом кейсе блокировки/разблокировки/смены пароля/восстановления — проверка статуса SIM и баланса ДО и ПОСЛЕ операции.
