#### ТЕСТ-КЕЙС: TC-SCN-001-01 — Успешная авторизация с валидным сертификатом КЭП
* **Тест-сьют:** Авторизация по КЭП (SCN-001)
* **Тип проверки:** Позитивная
* **Приоритет:** Critical
* **Предусловия:**
  - Пользователь имеет действующий сертификат КЭП
  - ИНН/ОГРН сертификата присутствует в базе разрешённых пользователей
  - CRL-сервер доступен (ответ < 3000ms)
* **Шаги воспроизведения:**
  1. Отправить POST-запрос на `/api/v1/auth/kep` с валидным PKCS#7/CMS-сообщением
  2. Проверить HTTP-статус код ответа
  3. Проверить наличие поля `access_token` (JWT) в теле ответа
  4. Декодировать JWT и проверить `exp` - `iat` = 900 секунд
  5. Использовать JWT для запроса к защищённому ресурсу (`GET /api/v1/user/profile`)
* **Ожидаемый результат:**
  - HTTP-статус: **200 OK**
  - `access_token` присутствует, `expires_in` = 900
  - Время жизни токена = 15 минут (900 сек)
  - Запрос к защищённому ресурсу успешен (200 OK)
* **Тестовые данные:**
  - Валидный PKCS#7 CMS с сертификатом, ИНН=7701002001, срок действия до 2027-01-01

#### ТЕСТ-КЕЙС: TC-SEC-01 — Блокировка УЗ после 5 неудачных попыток авторизации
* **Тест-сьют:** Безопасность (S3)
* **Тип проверки:** Негативная
* **Приоритет:** Critical
* **Предусловия:** Учётная запись активна, не заблокирована
* **Шаги воспроизведения:**
  1. Выполнить 5 последовательных попыток авторизации с неверным КЭП
  2. Проверить статус/код ответа для каждой попытки
  3. На 6-й попытке отправить валидный КЭП
  4. Проверить код ответа
  5. Зафиксировать время блокировки
  6. Через 30 минут повторить попытку с валидным КЭП
  7. Проверить код ответа
* **Ожидаемый результат:**
  - Попытки 1-5: 401 Unauthorized
  - Попытка 6: **423 Locked** — учётная запись временно заблокирована
  - Тело ответа: `"error": "account_locked", "lock_duration_min": 30`
  - Через 30 минут: **200 OK**, JWT-токен выдаётся
* **Тестовые данные:**
  - Неверный КЭП: подпись не соответствует сертификату
  - Аккаунт: ИНН=7701002001
