# Confluence Review Report

## Требование: Ручная корректировка баланса для роли SupportOps с лимитом 5 000 руб.

**Источник:** Спецификация «Личный кабинет B2B-оператора связи» v1.1.0, страница Confluence ID: 458753
**Компоненты:** access_matrix.balance_adjustment, SCN-003 (SupportOps), UI-форма редактирования баланса

| ID | Исходный фрагмент текста | Описание дефекта/риска | Критичность | Рекомендация по исправлению |
| :--- | :--- | :--- | :--- | :--- |
| REQ-01 | `balance_adjustment.SupportOps = ALLOWED_WITH_LIMIT_5000_RUB` + сценарий «Ввод суммы до 5000 руб.» | **Граничная неопределенность:** Не указано, включается ли значение 5 000.00 руб. в лимит (≤ 5 000 или < 5 000). Разные части системы могут трактовать «до» по-разному. | **High** | Явно указать строгость границы: `max_limit = 5000.00` (включительно) или `max_limit = 4999.99` (исключая 5000). |
| REQ-02 | Сценарий SCN-003 описывает только `type = "Начисление" (credit)` | **Неполнота:** Матрица доступа определяет `balance_adjustment` в целом, но сценарий описывает только операцию начисления. Непонятно, действует ли лимит 5 000 руб. на операцию **списания (debit)** и применяется ли он к транзакции в целом. | **Medium** | Дополнить сценарий двумя вариантами: начисление (credit) и списание (debit), явно указав, применяется ли лимит к сумме операции без учета знака. |
| REQ-03 | `balance_adjustment.SupportOps = ALLOWED_WITH_LIMIT_5000_RUB` | **Неопределенность периода:** Лимит 5 000 руб. — это ограничение на одну транзакцию, на день, на месяц или на сессию? Термин «разового изменения» в UI-валидации указывает на одну операцию, но в матрице это не специфицировано. | **Medium** | Явно указать в спецификации: `limit_type = "per_transaction"` (или `per_day`/`per_session`) с соответствующими числовыми значениями. |
| REQ-04 | Сценарий SCN-003 отсутствует для значения 0.00 и отрицательных сумм | **Пропуск граничных условий:** Не определено поведение системы при попытке корректировки баланса на сумму 0.00 руб. или отрицательное значение (при выбранном типе «Начисление»). | **Low** | Добавить описание реакции UI/API на нулевую и отрицательную сумму корректировки. |
| REQ-05 | `Запись действия в лог с тегом роли` | **Неполнота структуры лога:** Не указано, какие именно поля фиксируются в аудит-логе (сумма, тип операции, ID абонента, timestamp, IP-адрес, результат). Отсутствие спецификации может привести к расхождению между фактической записью и ожиданиями SecurityOps при аудите. | **Medium** | Описать обязательный набор полей аудит-лога для операции корректировки баланса: `{timestamp, actor_id, role, account_number, amount, type, result, ip_address}`. |
