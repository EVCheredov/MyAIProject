## 1. Назначение фичи
Управление учётными записями и аутентификацией абонентов в личном кабинете оператора «Super GSM».

## 2. Роли пользователей
| Роль | Описание |
|------|----------|
| Абонент | Владелец учётной записи, входит в личный кабинет |
| Администратор | Управляет блокировкой/разблокировкой учётных записей |
| Система аутентификации (Auth Service) | Проверяет учётные данные и управляет сессиями |

## 3. Функциональные требования

### FR-01. Аутентификация абонента
- Абонент входит в личный кабинет по паре «логин (MSISDN) + пароль».
- При успешной проверке учётных данных система создаёт сессию и предоставляет доступ к личному кабинету.
- При неверном пароле система возвращает ошибку аутентификации.

### FR-02. Политика пароля
- Минимальная длина пароля — 8 символов.
- Максимальная длина пароля — 64 символа.
- Пароль должен содержать не менее одной заглавной буквы, одной строчной буквы и одной цифры.
- Пароль хранится в виде необратимого хеша.

### FR-03. Блокировка учётной записи
- После **3 последовательных неудачных попыток** ввода пароля учётная запись блокируется.
- Учётная запись в состоянии «Заблокирована» не допускает входа даже при вводе верного пароля.
- Разблокировка выполняется администратором вручную.

### FR-04. Управление сессией
- Время жизни сессии (TTL) — **30 минут** с момента последней активности.
- По истечении TTL сессия завершается, требуется повторный вход.
- При смене пароля все активные сессии абонента инвалидируются.

### FR-05. Восстановление доступа
- Абонент может восстановить пароль через подтверждение по SMS-коду.
- SMS-код направляется на MSISDN, привязанный к учётной записи.

## 4. Бизнес-правила
| ID | Правило |
|----|---------|
| BR-01 | Счётчик неудачных попыток сбрасывается после успешного входа. |
| BR-02 | Блокировка не изменяет статус SIM-карты в сети. |
| BR-03 | Все события аутентификации пишутся в журнал аудита. |

## 5. Тестовые данные
- MSISDN для тестов: `[PHONE_MASKED]`, `[PHONE_MASKED]`.
- Пароль-пример: `SuperGsm2024`.

## 6. Замечания по контексту
Требования полные по объёму Happy Path и основным веткам отклонения. Критических противоречий в описании бизнес-логики не выявлено.
