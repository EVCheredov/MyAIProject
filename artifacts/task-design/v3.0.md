### ЗАДАЧА 1: KAN-22 — Тестирование: Аутентификация абонента (вход по MSISDN + пароль)

* **Тип задачи:** Тестирование
* **Описание:** Проверить механизм входа по паре «логин (MSISDN) + пароль», создание сессии при успехе, обработку неверного пароля/логина и неразличимость ответов для клиента (FR-01, BR-03).
* **Предусловия / Зависимости:** Развёрнуты Auth Service и Session Manager; доступны тестовые MSISDN [PHONE_MASKED]. Выполняется параллельно, поставляет тестовые данные для задач про сессии и блокировку.
* **Критерии приемки (Acceptance Criteria):**
  - [ ] Успешный вход с корректными MSISDN + паролем → создаётся сессия, предоставляется доступ
  - [ ] Неверный пароль → HTTP 401 {"errorCode":"AUTH_INVALID_CREDENTIALS"}
  - [ ] Несуществующий логин → HTTP 401 с идентичным телом ответа
  - [ ] Ответы на неверный логин и неверный пароль неразличимы (защита от перебора)
  - [ ] Успешная аутентификация зафиксирована в журнале аудита (BR-03)
  - [ ] Неудачная попытка зафиксирована в журнале аудита (BR-03)
  - [ ] Проверены статус и баланс абонента до и после входа (телеком-валидация)

### ЗАДАЧА 2: KAN-23 — Тестирование: Политика пароля (валидация, Argon2id, защита от утечки)

* **Тип задачи:** Тестирование
* **Описание:** Проверить требования к паролю: правила валидации, способ хранения (Argon2id с солью) и защиту от попадания пароля/хеша в логи, трассировки, ответы API и аудит (FR-02, BR-04).
* **Предусловия / Зависимости:** Развёрнут модуль политики пароля; доступ к логам приложения, трассировкам и журналу аудита.
* **Критерии приемки (Acceptance Criteria):**
  - [ ] Границы длины: 7 → ошибка; 8 → успех; 64 → успех; 65 → ошибка (границы включительно)
  - [ ] Отсутствие ≥1 заглавной буквы → ошибка
  - [ ] Отсутствие ≥1 строчной буквы → ошибка
  - [ ] Отсутствие ≥1 цифры → ошибка
  - [ ] Спецсимволы разрешены, но не обязательны
  - [ ] Пароль хранится как необратимый хеш с солью (Argon2id), восстановление невозможно
  - [ ] Пароль не выводится в логи, трассировки, ответы API (ни открытым видом, ни хешем)
  - [ ] Пароль не попадает в журнал аудита (BR-04)

### ЗАДАЧА 3: KAN-24 — Тестирование: Блокировка учётной записи (порог, 30 мин, 423, разблокировка)

* **Тип задачи:** Тестирование
* **Описание:** Проверить механизм блокировки при неудачных попытках входа, автоматическое/ручное снятие блокировки, сброс счётчика и отсутствие влияния на SIM/баланс (FR-03, BR-01, BR-02, BR-03).
* **Предусловия / Зависимости:** Доступны Login и счётчик попыток; доступен админ-интерфейс ручной разблокировки; доступ к журналу аудита и данным статуса SIM/баланса (источник — Биллинг).
* **Критерии приемки (Acceptance Criteria):**
  - [ ] После 3 последовательных неудачных попыток — блокировка на 30 минут
  - [ ] В состоянии «Заблокирована» вход запрещён даже при верном пароле → HTTP 423 {"errorCode":"ACCOUNT_BLOCKED","retryAfterSeconds":<остаток>}
  - [ ] По истечении 30 минут блокировка снимается автоматически, счётчик обнуляется
  - [ ] Администратор может снять блокировку вручную досрочно; действие фиксируется в журнале аудита
  - [ ] Счётчик сбрасывается после успешного входа (BR-01)
  - [ ] Счётчик сбрасывается после истечения блокировки (BR-01)
  - [ ] Блокировка не изменяет статус SIM и не влияет на баланс; проверены до и после (BR-02)
  - [ ] События блокировки и разблокировки зафиксированы в журнале аудита (BR-03)

### ЗАДАЧА 4: KAN-25 — Тестирование: Управление сессиями (TTL, продление, инвалидация, logout)

* **Тип задачи:** Тестирование
* **Описание:** Проверить управление сессиями: TTL 30 минут с последней активности, продление при активности, истечение, инвалидацию при смене пароля и поведение logout (FR-04).
* **Предусловия / Зависимости:** Доступны Login и Session Manager; доступен сценарий смены пароля. Зависит от успешной аутентификации (KAN-22).
* **Критерии приемки (Acceptance Criteria):**
  - [ ] TTL сессии = 30 минут с последней активности
  - [ ] Каждая успешная операция продлевает TTL
  - [ ] По истечении TTL → HTTP 401 {"errorCode":"SESSION_EXPIRED"}, требуется повторный вход
  - [ ] Смена пароля инвалидирует все активные сессии, включая текущую
  - [ ] Logout завершает только текущую сессию (другие сессии активны)
  - [ ] Проверены статус и баланс абонента до и после смены пароля (телеком-валидация)

### ЗАДАЧА 5: KAN-26 — Тестирование: Восстановление доступа по SMS-коду

* **Тип задачи:** Тестирование
* **Описание:** Проверить восстановление пароля через SMS-код: отправка на привязанный MSISDN, срок действия, лимит попыток, повторный запрос и защиту кода от утечки (FR-05, BR-04).
* **Предусловия / Зависимости:** Доступен SMS-шлюз (или мок); доступна привязка MSISDN к учётной записи. Зависит от модуля политики пароля (KAN-23) для валидации нового пароля.
* **Критерии приемки (Acceptance Criteria):**
  - [ ] Восстановление выполняется через подтверждение по SMS-коду
  - [ ] SMS-код направляется на MSISDN, привязанный к учётной записи
  - [ ] Код действителен 5 минут
  - [ ] 3 попытки ввода; после 3 неудачных код аннулируется и требуется повторный запрос
  - [ ] После успешного подтверждения пароль меняется (с валидацией по FR-02)
  - [ ] SMS-код не попадает в журнал аудита и технические логи (BR-04)
  - [ ] Проверены статус и баланс абонента до и после смены пароля (телеком-валидация)

### ЗАДАЧА 6: KAN-27 — Тестирование: Обработка ошибок аутентификации (503/502, таймауты)

* **Тип задачи:** Тестирование
* **Описание:** Проверить обработку недоступности Auth Service и недоставки SMS, включая коды ответов, таймауты и ограничение повторного запроса (FR-06).
* **Предусловия / Зависимости:** Возможность эмулировать недоступность Auth Service и недоставку SMS; доступ к настройке таймаута обращения к Auth Service.
* **Критерии приемки (Acceptance Criteria):**
  - [ ] Недоступность Auth Service → HTTP 503 {"errorCode":"AUTH_SERVICE_UNAVAILABLE"}
  - [ ] Таймаут обращения к Auth Service = 5 секунд (проверено фактическое поведение)
  - [ ] Недоставка SMS → HTTP 502 {"errorCode":"SMS_DELIVERY_FAILED"}
  - [ ] Повторный запрос SMS-кода возможен не ранее чем через 60 секунд

### ЗАДАЧА 7: KAN-28 — Тестирование: Журнал аудита и защита секретов (BR-03, BR-04)

* **Тип задачи:** Тестирование
* **Описание:** Проверить сквозные бизнес-правила аудита и защиты секретов: полноту фиксации событий аутентификации и отсутствие пароля/SMS-кода в аудите и технических логах (BR-03, BR-04).
* **Предусловия / Зависимости:** Выполнены сценарии аутентификации, блокировки/разблокировки, восстановления доступа (KAN-22, KAN-24, KAN-25, KAN-26); доступ к журналу аудита и техническим логам.
* **Критерии приемки (Acceptance Criteria):**
  - [ ] Событие «успешный вход» зафиксировано в журнале аудита (BR-03)
  - [ ] Событие «отказ в аутентификации» зафиксировано в журнале аудита (BR-03)
  - [ ] Событие «блокировка» зафиксировано в журнале аудита (BR-03)
  - [ ] Событие «разблокировка» (в т.ч. ручная) зафиксировано в журнале аудита (BR-03)
  - [ ] Пароль отсутствует в журнале аудита и технических логах (BR-04)
  - [ ] SMS-код отсутствует в журнале аудита и технических логах (BR-04)
